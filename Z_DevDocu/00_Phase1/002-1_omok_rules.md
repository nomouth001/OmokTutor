## 3. 좌표계 — `cell_id` SSOT

### 3.1 ID 형식

```
R{RR}C{CC}
```

| 필드 | 값 |
|------|-----|
| `RR` | `00`~`14` (행, 2자리, 0-indexed) |
| `CC` | `00`~`14` (열, 2자리, 0-indexed) |

**예:** `R07C07` = 천원(보드 정중앙). `R00C00` = 좌상단 모서리.

- 정규식: `^R(0[0-9]|1[0-4])C(0[0-9]|1[0-4])$`
- UI 표시용 관례 좌표(예: 렌주 표기 `H8`)로의 변환은 **L1 렌더링 레이어의 책임**이며 엔진 SSOT는 항상 `cell_id`를 사용한다.

### 3.2 방향 벡터 (4방향, 결정론 순서 고정)

| `direction_id` | 벡터 `(dRow, dCol)` | 설명 |
|:---:|:---:|------|
| `H` | `(0, 1)` | 가로 |
| `V` | `(1, 0)` | 세로 |
| `D1` | `(1, 1)` | 대각선 ↘ |
| `D2` | `(1, -1)` | 대각선 ↙(↗ 방향 줄과 동일선) |

- 각 줄의 판정은 해당 방향과 그 반대 방향(`-dRow, -dCol`)을 모두 포함해 **새 돌을 중심으로 좌우 대칭 탐색**한다.

### 3.3 보드 초기화

- 전체 225칸 `EMPTY`로 초기화. 사전 배치 없음(오프닝 룰 미구현, §1.3).

## 5. 턴 진행 (핵심 루프)

### 5.1 상태·이벤트 (L1 상태 머신)

```
SETUP → TURN_LOOP
TURN_LOOP:
  → PLACE_STONE(active)
  → [active == BLACK AND ruleset == renju ?] FORBIDDEN_CHECK (§8)
      → 금수면 PLACE_STONE 자체가 거부됨(§8.9) — 턴 소비 없음, 유저 재선택
  → WIN_CHECK (§6)
      → 오목 성립 시 ROUND_END(승리)
  → DRAW_CHECK (§7)
      → 보드 만석 시 ROUND_END(무승부)
  → 다음 플레이어(`active = 1 - active`)
```

모든 전이는 `GameLog`에 `event_type` 기록 (003).

### 5.2 `PLACE_STONE` (착수)

입력: `player_id`, `cell_id` (해당 칸이 `EMPTY`여야 함, 렌주 흑 금수 칸이 아니어야 함).

1. 대상 칸이 `EMPTY`가 아니면 **입력 거부**(`INVALID_MOVE`, 턴 소비 없음).
2. `active == BLACK` AND `ruleset_id == omok_renju_15_v1`이면 §8 금수 판정 선행. 금수 칸이면 **입력 거부**(`FORBIDDEN_REJECTED`, 턴 소비 없음).
3. 통과 시 해당 칸에 `active` 색 배치, `PLACE_STONE` 이벤트 기록.

### 5.3 턴 종료

- 유효한 1회 착수 후 즉시 §6 승리 판정 → §7 무승부 판정 순으로 검사.
- 둘 다 아니면 `active = 1 - active`로 교대.

## 6. 승리 판정 (§2 "오목")

### 6.1 판정 시점

매 `PLACE_STONE` 성공 직후, **새로 놓은 돌을 지나는 4개 줄만** 검사(전체 보드 재스캔 불필요 — 결정론·성능 고정).

### 6.2 줄별 최대 연속 길이 계산

각 `direction_id`(§3.2)에 대해, 새 돌 위치에서 양쪽으로 **같은 색**이 끊길 때까지 확장해 연속 길이 `run_length`를 구한다.

### 6.3 판정 표

| `ruleset_id` | `run_length == 5` | `run_length >= 6` |
|--------------|:---:|:---:|
| `omok_freestyle_15_v1` | **승리** (해당 색) | **승리** (해당 색, 장목도 승리로 인정) |
| `omok_renju_15_v1`, 백(P1)이 놓은 경우 | **승리** | **승리** (백은 장목 제한 없음) |
| `omok_renju_15_v1`, 흑(P0)이 놓은 경우 | **승리** | **승리 아님** — §8.6 장목 금수 (단, 애초에 §8.9 배치 차단으로 이 상태 자체가 발생하지 않음이 MVP 기본) |

- 4방향 중 **하나라도** 승리 조건을 만족하면 즉시 `ROUND_END(winner=active_player)`. 나머지 방향은 검사하지 않음(결과 불변, 성능 최적화).

## 8. 렌주 금지수 (○-lite) — 흑(P0) 전용

> `ruleset_id == omok_freestyle_15_v1`이면 본 §8 전체가 **비활성**(금수 없음). 아래는 `omok_renju_15_v1`에만 적용.

### 8.1 공통 원칙

1. **오목(정확히 5)이 최우선** — 이번 수로 §6의 오목 승리 조건을 만족하면, 같은 수가 동시에 삼삼·사사 패턴을 만들더라도 **금수가 아니며 즉시 승리**한다(§8.7 알고리즘 1단계에서 선판정).
2. **사삼(四三) 콤보는 금수 아님** — 같은 수로 사(四) 1개 + 활삼 1개를 동시에 만드는 것은 **합법**이다. 금지되는 것은 **같은 종류가 2개 이상**(삼삼 = 활삼 2개↑, 사사 = 사 2개↑)일 때뿐이다.
3. **장목은 그 자체로 금수** — 오목(정확히 5)이 아니라 6개 이상이 되면, 삼삼·사사 여부와 무관하게 금수(§8.6).
4. 판정은 **새로 놓은 흑돌을 지나는 4개 줄**만 검사한다(§6.2와 동일 범위).

### 8.2 활삼(open three) ○-lite 정의

새 돌을 지나는 한 줄에서, 아래 패턴이 존재하면 그 줄을 **활삼**으로 카운트한다.

```
패턴:  . B B B .
```

- `B` = 흑돌 3개 연속(새 돌 포함), 양 옆 `.`(빈 칸) 각 1칸.
- **조건:** 두 `.` 중 **어느 쪽에 흑돌을 추가해도** 그 결과가 **막히지 않은 사(관련 두 칸 중 최소 한쪽이 여전히 빈 칸으로 남아 오목 완성 가능)** 가 되어야 한다 — 즉 `. . B B B . .` 형태처럼 **양쪽 확장 여지가 모두 살아있는 경우만** 활삼으로 인정한다. 한쪽이 보드 밖이거나 백돌로 막혀 있으면(`x B B B .` 형태, `x`=백돌 또는 보드 밖) 그 줄은 활삼이 아니다.
- **○-lite 제외:** 틈형 활삼(예: `. B B . B .` 류의 "broken three")은 MVP 판정 대상에서 **제외**한다 — 프로 렌주 세칙의 세부 사례이며 §1.3에 따라 후속 과제로 미룬다. 이 경우 L2·복기에는 `RENJU_BROKEN_THREE_UNSUPPORTED` 한계 플래그를 남긴다.

### 8.3 사(四, four) ○-lite 정의

새 돌을 지나는 한 줄에서, 그 줄의 9칸 구간(새 돌 좌우 각 4칸)을 검사해 **정확히 1개의 빈 칸에 흑돌을 놓으면 그 줄의 연속 길이가 정확히 5가 되는 경우**, 그 줄을 **사(四)**로 카운트한다.

- 직선형(`. B B B B .`)과 틈형(`B B . B B`, `B . B B B`, `B B B . B`)을 **모두 포함**한다 — 사는 활삼과 달리 틈형도 실전에서 매우 흔해 ○-lite에서도 포함한다.
- 그 하나의 완성 칸을 놓았을 때 결과가 **정확히 5**(6 이상 장목이 아님)여야 "사"로 카운트한다. 완성 시 6 이상이 되는 형태는 사가 아니라 §8.6 장목 경로로 별도 처리한다(놓았을 때 장목이 되는 그 칸 자체는 흑에게 금수 칸이 되므로, 사 카운트에서 자연히 제외됨).

### 8.4 삼삼(33) 금지

새 수 하나가 **서로 다른 2개 이상의 줄**에서 동시에 §8.2 활삼을 만들면 **금수**(`forbidden_reason = double_three`).

### 8.5 사사(44) 금지

새 수 하나가 **서로 다른 2개 이상의 줄**에서 동시에 §8.3 사(四)를 만들면 **금수**(`forbidden_reason = double_four`).

### 8.6 장목(overline) 금지

새 수로 인해 어느 한 줄의 연속 길이가 **6 이상**이 되면 **금수**(`forbidden_reason = overline`) — §8.1 원칙 1에 따라 이 수가 **동시에 다른 줄에서 정확히 5**를 만들지 않는 한(그 경우 오목 승리가 우선).

### 8.7 판정 알고리즘 (결정론 순서)

흑이 `cell_id`에 두려는 시도가 있을 때:

```
1. 해당 칸에 흑돌을 가상 배치한다.
2. 4개 줄 각각의 run_length를 계산한다 (§6.2 방식).
3. run_length == 5 인 줄이 하나라도 있으면 → LEGAL, 즉시 승리(§6). (이하 단계 생략)
4. run_length >= 6 인 줄이 하나라도 있으면 → FORBIDDEN(overline). 종료.
5. §8.3 기준으로 4개 줄 각각 "사" 여부를 판정, 개수를 센다.
   → 사 개수 >= 2 → FORBIDDEN(double_four). 종료.
6. §8.2 기준으로 4개 줄 각각 "활삼" 여부를 판정, 개수를 센다.
   → 활삼 개수 >= 2 → FORBIDDEN(double_three). 종료.
7. 위 4~6에서 FORBIDDEN이 없으면 → LEGAL.
```

### 8.8 ○-lite 미구현 범위

- §8.2 틈형(broken) 활삼 미판정(§8.2 명시)
- 다중 금수(예: 삼삼+사사 동시 발생 시 사유 라벨은 **먼저 검사된 것 하나만** 기록 — §8.7 순서상 `double_four`가 `double_three`보다 우선 라벨링됨. 실제로는 두 사유 모두 발생했어도 사용자에게는 대표 사유 1개만 노출)
- 렌주 심판 규정의 "5수 이상 연속 금수 판정 특례" 등 초정밀 사례 전부

### 8.9 금수 집행 방식 (MVP 기본값)

| 방식 | 설명 | 채택 |
|------|------|:---:|
| **배치 차단(block_placement)** | L1 UI가 흑 차례에 금수 칸을 사전 계산해 **선택 자체를 막음**(회색 처리·클릭 무시) — §8.7 알고리즘을 흑의 매 착수 후보 전체 칸에 대해 미리 돌려 표시 | **MVP 기본** |
| **즉시 패배(instant_loss)** | 흑이 금수 칸에 실제로 두면 그 순간 반칙패 처리 | Post-MVP 옵션(`001-1` §8.2 C3 "금지수 위반" 패착 코칭과 연동 시 고려) |

- 코칭 앱 취지상 "몰라서 지는" 경험보다 "왜 여기 못 두는지 미리 알려주는" 경험이 학습에 유리하므로 **배치 차단을 기본값**으로 고정한다.
- `features.forbidden_enforcement: "block_placement" | "instant_loss"` 플래그로 003에서 표현한다.

### 9.1 필수 `event_type` (003에서 enum 확정)

### 9.2 `forbidden_reason` (MoveEvent, 003)

`none` | `double_three` | `double_four` | `overline`

### 9.3 L2 입력 팩트 (002가 보장하는 팩트)

| 팩트 | 출처 |
|------|------|
